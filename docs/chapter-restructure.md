### 6.1 給老師的遷移操作步驟（`npm run chapters:migrate`）

> 〔CH-A 補〕工具：`exam_pro/scripts/migrate_chapters.js`；關鍵字規則：`exam_pro/config/chapterMigrationRules.js`；設計理由：ADR-016。
> 這支工具**不呼叫 AI、不花錢**，只讀寫你自己的資料庫。

**為什麼要做**：章節重整之後，題庫裡的舊題還掛著舊章名（例如「三次函數」「三角函數的定義」）。不搬的話，這些題在編輯視窗存不回去（舊章名不在新白名單），弱點統計和題庫覆蓋率也對不上新章。改名的章可以自動搬；拆成好幾章的、被刪掉的章，要看題目內容才知道放哪裡，所以流程是「電腦先提議 → 你確認 → 再套用」。

**什麼時候做**：上線時 `npm run migrate` 之後（第 6 條第 1 步）。最好在重整後第一次上傳新考卷**之前**做完——之後新上傳的題 AI 會直接用新章分類，混在一起你會多看很多題。

1. **先備份**：`npm run db:backup`。
2. **套用資料庫更新**：`npm run migrate`（這次多一支 `0014_chapter_migration_log.sql`，用來記錄哪些題已經處理過）。
3. **產生提議檔**：`npm run chapters:migrate`
   - 會在 `exam_pro/data/` 產生 `chapter-migration-<今天日期>.csv`，並印出統計：哪幾章有幾題、各提議搬去哪裡。
   - 這一步**只讀不寫**，跑幾次都沒關係。同一天再跑會存成 `…-2.csv`，不會蓋掉你正在改的那份。**第 6 步只套用最新一份（你改過的那一份）提議檔**，舊的那份不要再套；萬一套了，已經套用過的題工具會略過並列出，不會再搬一次。
   - 章名既不在新白名單、也不在對照表的題（多半是舊系統匯入時的髒資料），會另外列出題號，請在題庫頁手動改章。
   - 沿用舊名的 10 章（排列、組合、古典機率、指數與對數、正弦與餘弦定理、隨機變數、動量與衝量、動量守恆與碰撞、剛體轉動與平衡；〔CR-8〕加上直線方程式）只列第 2 步**之前**入庫的題；之後新上傳的題 AI 已經用新章節分類，只印出題數、不列進提議檔。想一起看的話加 `-- --include-new`。
4. **用 Excel 打開提議檔，逐列確認**。六個欄位：

   | 欄位 | 說明 | 要不要改 |
   |---|---|---|
   | id | 題號（題庫頁可用題號找到整題） | 不要改 |
   | subject | 數學或物理 | 不要改 |
   | 舊章 | 這題現在的章 | 不要改 |
   | **提議新章** | 電腦建議搬去的章 | **不同意就直接改這一格** |
   | 依據 | 電腦為什麼這樣建議（見下表） | 不用改 |
   | 題幹前60字 | 幫你認題目；已封存的題前面有「（已封存）」 | 不用改 |

   「依據」怎麼看：

   | 依據 | 意思 | 建議 |
   |---|---|---|
   | `rename` | 舊章只是改名（多項式除法 → 多項式的運算與應用） | 通常直接接受 |
   | `keyword:<詞>` | 舊章拆成好幾章，題幹（或入庫時 AI 抽的關鍵詞）出現了這個詞 | 看一下這個詞是不是真的是這題在考的觀念（例：題目寫「從集合 {1,2,3} 取數排列」會被「集合」拉到集合與計數原理，但它其實是排列題） |
   | `default` | 舊章拆成好幾章，但沒有任何關鍵詞命中，提議的是預設去處 | **最需要看**；很多會是「留在原章」（提議新章與舊章相同） |
   | `removed` | 舊章已刪除（物理：流體的壓力與浮力、宇宙學簡介） | **一定要決定**；流體那章沒有建議去處，「提議新章」是空的，必須填上 |

   - 改章時，章名要和新白名單一模一樣（題庫頁「章節」下拉選單裡的寫法，或看 `exam_pro/config/chapterPlan.js`）。全形／半形括號、多打的空白會自動容許。
   - **同意留在原章**：「提議新章」寫原本的章名（`default` 的列多半已經是這樣）。
   - **這題想晚點再決定**：把整列刪掉。下次再跑第 3 步，只會列出還沒處理的題。
   - 已封存的題也要處理：學生的作答紀錄還在，弱點統計會用到它的章。
5. **存檔**：Excel「另存新檔」選「**CSV UTF-8（逗號分隔）**」。選成一般的「CSV（逗號分隔）」也可以，工具會自動辨識（Big5）。
6. **套用**：`npm run chapters:migrate -- --apply "data/chapter-migration-<日期>.csv"`
   - 先逐列檢查：題號存在、科目對得上、新章在白名單內、沒有空白、沒有重複列。**只要有一列有問題，整批都不寫**，並列出第幾行、什麼問題；改好再跑一次即可。
   - 全部通過才一次寫入（單一交易，不會寫一半）。會印出：搬到新章幾題、確認留在原章幾題、已經是新章（重跑）幾題、清掉幾筆 AI 知識點標註。
   - 搬過章的題：章節來源標成「人工」、AI 標的知識點清掉（它是從舊章的知識點挑的），**你自己標的知識點保留**。
   - 產生提議檔之後你又在題庫頁改過章的題，工具會略過並列出來（以你後來改的為準）。
   - **同一份 CSV 再套一次不會重複改**；套用過的題之後的第 3 步也不會再列出。
   - **套用過的題一律不再改**：同一天的另一份提議檔、或搬完之後你在題庫頁又把題目改回原來的章（例如搬到集合與計數原理後又改回排列），再套用時都會略過並列出「此題已於先前套用，略過」，以第一次套用與你之後在題庫頁改的為準。
7. **跑印出來的兩個指令**（第 6 條第 2 步與原本的 `search:reindex`）：
   - `npm run embed:backfill`：搬過章的題重算向量（會呼叫 embedding API，費用很小）。
   - `npm run search:reindex`：章名和分詞詞典都改了，全部題目的關鍵字索引重切（不花錢）。
   - 之後照原順序 `npm run kc:load` 載入新的知識點。被清掉 AI 知識點標註的題，可以再用 `npm run kc:backfill` 依新章重標（會呼叫 AI，先加 `-- --dry-run` 看題數與費用）。

補充：
- **還在「待複核」的拆題結果**不在提議檔裡（它們還沒入庫）。按「入庫」時會用新白名單檢查，舊章名會被擋下，請在複核畫面把章節改成新章再入庫。
- **想反悔**：用第 1 步的備份還原；或在題庫頁把個別題改回你要的章（新白名單內）。每一題搬了什麼、依據是什麼，都記在資料庫的 `chapter_migration_log` 表。
