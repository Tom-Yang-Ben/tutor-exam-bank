## 5. DEDUP_DUP_THRESHOLD（現行 0.97）與 DEDUP_VARIANT_THRESHOLD（現行 0.9）

dedup1 的判定（`agents/dedup.js`）：與同科最近一題的餘弦 ≥ DEDUP_DUP_THRESHOLD → 回 fail／`duplicate`，dedup1 沒有重試，經 `pipeline/stateMachine.js` 的 `REVIEW_REASON_FOR_FAIL` 進複核（`review_reason='duplicate'`；不自動入庫、也不刪，老師決定）；≥ DEDUP_VARIANT_THRESHOLD → 標「變式」照常往下走（只是標記）；其餘 unique。

**變式 job 的 dedup1 排除藍本整個家族**：`workers/jobRunner.js` 給 dedup1 的 input 多一個 `exclude_family_root`（＝藍本的家族根），`agents/dedup.js` 的候選 SQL 加 `AND COALESCE(variant_of, id) <> 家族根`，變式存檔時 `variant_of`＝家族根。所以**同一藍本的變式（兄弟）在 dedup1 永遠不會互相比對**，任何門檻都一樣；只有逐字相同（正規化後）的會被 dedup0 的 L0 雜湊擋下（同一個 job 較早的題，或已入庫的題）。5.3 比的是「生成題 vs 別的家族的題」，這在產品裡會比；5.4 的兄弟之間只是「換句話說」的餘弦代理。
