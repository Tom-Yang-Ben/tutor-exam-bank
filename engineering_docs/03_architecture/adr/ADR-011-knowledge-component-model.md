## 1. 背景與問題

- **上下文**: 弱點面板以「章節」為單位（階段 3）。章節太粗：「向量內積」錯誤率高，老師仍不知道學生卡在坐標算法、正射影還是柯西不等式；補救出題與 AI 家教也就只能對整章下手。缺口分析 G02 要求一個比章節更細的診斷單位（每章 3–8 個），而 Owner 另外要求每個單位附一段「口語版」——老師上課的講法——讓 AI 家教的說法與上課一致。
- **問題**: 知識點的識別方式、內容的權威來源、題目—知識點關聯的產生方式，三者都要定下來，而且必須讓 WS-D（弱點、補救卷）與 WS-E（家教）在沒有彼此程式碼的情況下平行開發。
- **驅動因素/約束**:
  - 內容量大（數學 34 章、物理 32 章、化學 44 章，數百個知識點），只能由 AI 草擬、Owner 逐章審定；審定是最貴的人力，不能被重新載入蓋掉。
  - 既有 cassette 一律不得失效（第 1.1 條）：不能改既有 agent 的模板或 schema 值域。
  - 題庫已有數百題；新題每週由管線入庫。標註必須能批次回填，也必須能在入庫時自動發生，但不能讓入庫因此變得不可靠。
  - 老師手動修正的標註必須永遠優先——自動流程覆寫人工判斷，正是 kNN 投票設計時明文避開的閉環放大器（`docs/interfaces-stage3.md` 第 5.2 條：只有人工標籤有投票權）。

## 2. 考量的選項

### 選項一: 以自增 id 識別、內容直接存 DB、AI 標註覆寫一切
- **描述**: 知識點只有 id；內容由管理介面輸入；自動標註每次重算並覆寫該題的全部關聯。
- **優點**: 最少的程式碼與欄位。
- **缺點**: id 隨載入順序而變，種子檔無法描述先備關係、跨環境無法對照；沒有審定狀態，重新匯入會蓋掉 Owner 的修改；AI 覆寫人工標註，老師修一次、下次回填又被改回去。
- **成本/複雜度**: 低

### 選項二: 以 code 識別、種子檔＋審定狀態、AI 與人工標註分權（採用）
- **描述**: `code = MATH|PHYS|CHEM.<章名>.<兩位序號>` 是穩定識別碼；內容來自 `config/kc/<科目>.json` 種子檔，`status` 分 `draft`／`approved`，載入腳本不覆寫已審定列（除非 `--force`）；`question_kcs.src` 分 `ai`／`human`：人工以 PUT 取代全部，自動標註遇到任何 human 列就不動、只取代自己寫過的 ai 列；AI 標註走新的 agent `kc_tag`，schema 的 enum 為該章 codes（動態）。
- **優點**: 種子檔、先備、標註、cassette 都有穩定的鍵；Owner 的審定被結構性保護；人工永遠優先；新 agent 不碰既有模板，cassette 不失效；該章清單以 enum 限制，跨章錯配在 schema 層就被擋掉。
- **缺點**: code 內含章名，改章名等於換 code（需要遷移）；「老師刻意清空某題標註」沒有欄位記住，回填會再挑到它；多一條 `kc:load` 的載入規則需要維護（先備同步、DB 層環檢查、同章換名的暫名兩段式更新）。
- **成本/複雜度**: 中

### 選項三: 以 108 課綱學習內容代碼為主鍵
- **描述**: 直接用課綱代碼（例如 N-11A-2）當知識點識別。
- **優點**: 有官方來源，看起來最「標準」。
- **缺點**: 課綱代碼粒度與教學順序不等於診斷需要的粒度（一條學習內容常涵蓋數個常見錯誤點）；物理、化學的選修內容對照不完整；AI 無法可靠產生正確代碼，編造的代碼比沒有更糟（第 3.4 條明文「不得編造」）。
- **成本/複雜度**: 中

## 3. 決策

**選擇**: 選項二——code 穩定識別、種子檔＋`draft`／`approved` 審定、口語版與課綱敘述分欄、AI 標註與人工標註以 `src` 分權；課綱代碼只作為可選欄位（有把握才填）。

**理由**:
- 穩定識別碼是平行開發的前提：KC 內容組只寫 code，WS-D、WS-E 只讀資料表，彼此不需要知道 id。
- 審定是最貴的資產，保護它的規則必須在載入器裡、而不是靠人記得；`--force` 保留為明確的破窗。
- 人工優先是既有系統已經學到的教訓（kNN 投票只信人工標籤）；把同一條原則延伸到知識點標註。
- 口語版與 `description` 分開：前者給學生聽、給家教沿用，後者是課綱式的精確敘述，給標註模型判斷。混成一欄，任一用途都會被另一個拖累。
- 動態 schema 讓「只能從該章挑」成為結構約束；伺服器端再以 ajv 與章節比對驗一次（裁決 S0-1 的延伸）。
- 入庫掛鉤採 fire-and-forget：標註是可回填的衍生資料，讓它的失敗影響入庫不成比例。

## 4. 後果

- **正面**: WS-D 的知識點弱點與補救卷、WS-E 的家教口語版，都能只依資料表開發；Owner 的審定不會被重新載入蓋掉；老師的手動修正永遠有效；既有 cassette 全部不失效；標註可在管線中自動發生，也可離線批次回填並先看預估費用。
- **負面**: 章名改動會讓 code 失效（要一次性遷移知識點、先備與標註）；「刻意不標」無法表達；自動標註的費用不進 `job_events`；只有經過管線 save 節點的新題會自動標，其他入口靠回填。
- **影響範圍**: `exam_pro/utils/kcSeed.js`（新增逐欄檢查與匯出）、`exam_pro/services/kcService.js`、`exam_pro/services/kcTagService.js`、`exam_pro/agents/tagKc.js`、`exam_pro/controllers/kcController.js`、`exam_pro/routes/index.js`（檔尾區塊）、`exam_pro/workers/jobRunner.js`（save 之後的單一掛鉤）、`exam_pro/scripts/load_kc.js`、`exam_pro/scripts/backfill_kc.js`、`exam_pro/public/js/kc.js`、`exam_pro/public/index.html`（`#kc` 路由的最小掛鉤）。
- **重新評估觸發**: 白名單章名需要改動（code 遷移）；老師反映「清空後又被標回去」；標註準確率 eval（待建）低於可接受水準，或人工修正率持續偏高；知識點數量或跨科先備複雜到需要圖資料庫等級的查詢。
